# Java Exercise Leaderboard

A static page that ranks participants across the FizzBuzz, REST API and framework upgrade exercises. It has no server and no build step. Participant status and scores live in `participants.csv`.

## Updating scores
Edit `participants.csv` (in Excel, a text editor, or GitHub's web editor) and commit. The page picks up the new file after GitHub Pages redeploys, usually within a minute or two.

| Column | Values |
|---|---|
| `name` | The participant's name. Rows with no name are skipped. |
| `github_username` | Their GitHub login (the PR author's `user.login`), without the `@`. Used to match PRs from the exercise repositories. |
| `fizzbuzz` | `correct`, `submitted` or `none`; FizzBuzz status from `meswright/excersize-1`. |
| `rest_api` | `correct`, `submitted` or `none`; REST API status from `AtulKumarSharma79/Onboardingtracker`. |
| `framework_upgrade` | `correct`, `submitted` or `none`; framework upgrade status from `AtulKumarSharma79/Frameworkupgrade`. |
| `stretch` | Number of additional stretch tasks completed manually. |
| `pr_stretch` | Generated by the sync script: number of PRs authored by the participant among the first three PRs in each exercise repo. Do not edit manually. |
| `helped` | Number of times the person helped a colleague |

Names containing a comma must be wrapped in double quotes, for example `"Rao, Asha"`.

Run `python3 sync_participants.py` from this folder to fetch PRs from all three exercise repositories and update the CSV. Participants with PRs are marked `submitted`; an existing `correct` status is preserved. Each of the first three PRs in each exercise repo earns its author one +5 stretch bonus. If the same author opened multiple of those first three PRs, they receive +5 for each PR. The script calculates `pr_stretch` from scratch each time, so rerunning it does not duplicate bonuses. New participants use their GitHub login as the display name. Existing rows without a `github_username` are preserved at the end and are not matched automatically.

The page ranks participants by total points (correct = 30, submitted = 10, each stretch credit = +5, each colleague helped = +5). It reads the CSV only; run the sync script and commit the resulting CSV to publish updated PR statuses and bonuses.

## Points
Submitted 10, correct solution 30, each stretch credit (including an early-PR bonus) +5, each time helping a colleague +5. To change the weights or exercise names, edit the `PTS` and `TRACKS` constants near the bottom of `index.html`.

## Trying it locally
Browsers block loading the CSV when `index.html` is opened straight from disk (double-clicked). Either:
- run `start.bat` (Windows, needs Python), which serves the folder and opens http://localhost:8000/index.html, or
- open `index.html` directly and use the **Choose participants.csv** button that appears.

To serve it by hand: `python -m http.server 8000`. To preview with made-up data, copy `participants.sample.csv` over `participants.csv` locally, and do not commit that copy.

## Publishing on GitHub Pages
1. Push this folder to a public repository.
2. In the repository, open **Settings**, then **Pages**.
3. Under **Build and deployment**, choose **Deploy from a branch**, pick the `main` branch and the `/ (root)` folder, and save.
4. The site appears at `https://<your-username>.github.io/<repository-name>/`.

The page and `participants.csv` are public, so anyone with the link can see every name and score.
